# Генерация клиентов и работа с API

Готовые шаблоны для переноса в проект лежат в `assets/api/`.

## Общий принцип

- Клиенты для backend API генерируются из OpenAPI-схем, а не пишутся вручную.
- Сгенерированный код отделяется от прикладной логики.
- Поверх generated-клиентов создаётся ручной слой сервисов, который:
  - маппит DTO в модели приложения
  - прячет особенности backend-контрактов
  - централизует обработку ошибок
  - не даёт тащить generated-типы и generated-методы глубоко в UI

## Как это устроено

- генерация запускается командой `npm run generate:api`
- команда вызывает `orval`
- конфиг генерации лежит в `orval.config.ts`
- generated-файлы складываются в `src/shared/api/services/@generated`
- для каждого backend/source используется свой mutator из `src/shared/api/client.ts`
- поверх generated-кода лежат ручные сервисы в `src/shared/api/services/*.service.ts`

В этом skill подготовлены шаблоны:

- `assets/api/orval.config.template.ts`
- `assets/api/client.template.ts`
- `assets/api/package.scripts.template.json`

## Что генерировать

Генерируй:

- методы запросов
- DTO и типы ответов
- параметры и request body типы

Не генерируй вручную:

- axios/fetch-методы для конкретных endpoint'ов
- DTO-типы, если они уже приходят из OpenAPI
- дублирующие типы только ради "удобства", если можно использовать generated-тип внутри сервисного слоя

## Где хранить код

- generated-клиенты: `src/shared/api/services/@generated`
- базовый API-клиент и mutator'ы: `src/shared/api/client.ts`
- ручные сервисы поверх generated-кода: `src/shared/api/services/*.service.ts`
- прикладные типы и маппинг DTO -> модель: рядом с сервисом или в том же сервисе, если объём небольшой

Не редактируй generated-файлы вручную.

## Генерация через Orval

Для генерации API-клиентов используй `orval` и придерживайся такой схемы:

1. Добавь или обнови OpenAPI source в `orval.config.ts`
2. Укажи target для generated-файла в `src/shared/api/services/@generated`
3. Подключи mutator из `src/shared/api/client.ts`
4. При необходимости настрой filters по tag'ам
5. Запусти генерацию
6. Проверь diff generated-файлов
7. Обнови ручные сервисы поверх generated-кода

За основу бери `assets/api/orval.config.template.ts`.

## Mutator и базовый клиент

Mutator нужен, чтобы generated-код не создавал транспорт сам, а использовал общий проектный клиент.

- есть общий `apiClient`
- он создаётся один раз в `src/shared/api/client.ts`
- в нём задаются baseURL, auth, retry, timeout и общие headers
- отдельные mutator-функции переключают нужный backend через `baseURL`

Практическое правило:

- общий transport, auth, retry, timeout и interceptors держи в одном месте
- generated-клиенты должны зависеть от этого слоя, а не от собственного локального `fetch/axios`

За основу для этого слоя бери `assets/api/client.template.ts`.

## Как работать с generated API в коде

Не импортируй generated-методы напрямую в UI-компоненты, pages или widgets.

Правильный поток:

1. generated API вызывается в `shared/api/services/*.service.ts`
2. сервис обрабатывает ошибки
3. сервис маппит DTO в понятные типы приложения
4. выше по слоям используется уже сервисный слой

Допустимо:

- импортировать `* as CoreApi` или аналогичный namespace в сервисе
- использовать generated DTO внутри маппинга

Нежелательно:

- вызывать `CoreApi.someEndpoint...` прямо из компонента
- разносить DTO-типы по feature/widget/page слою
- смешивать transport-логику, mapping и UI в одном месте

## Обработка ошибок

Ошибки backend-запросов обрабатывай в сервисном слое.

- generated-вызов оборачивается в `try/catch`
- ошибка приводится к `AxiosError`
- дальше проходит через общий helper обработки ошибок

Если в проекте уже есть общий helper наподобие `apiUtils.handleRequestError`, используй его.

## Маппинг DTO в модель приложения

Generated DTO почти всегда отражают backend-контракт, а не удобную модель для UI.

Поэтому:

- маппинг DTO -> доменная модель делай в сервисном слое
- не пробрасывай backend naming глубоко в приложение
- если backend отдаёт неудобную или нестабильную форму, нормализуй её в одном месте

Типовой пример:

- generated DTO содержит поля в стиле `snake_case`
- сервис преобразует их в модель, удобную для frontend-кода
- UI работает уже с нормализованной структурой

## Когда перегенерировать клиентов

Перегенерируй API-клиенты, если:

- изменился OpenAPI-контракт
- добавился новый endpoint
- изменились request/response DTO
- backend исправил контрактные ошибки и проект раньше держал workaround

После генерации обязательно проверь:

- нет ли сломанных импортов
- не изменились ли сигнатуры методов
- не сломался ли ручной mapping
- не появились ли лишние типы, которые лучше скрыть сервисным слоем

## Что ожидать от агента в таких задачах

Если задача связана с backend API, агент должен:

1. Найти существующий способ генерации клиентов в проекте
2. Не придумывать альтернативный API-слой без причины
3. Использовать generated-клиенты как источник контрактов
4. Добавлять ручной сервисный слой поверх generated-кода
5. Не редактировать generated-файлы вручную
6. После изменений перегенерировать клиентов, если этого требует контракт
