# AGENTS.md

## Область проекта

Этот репозиторий — сервис:

Работай только внутри этого репозитория, если в задаче явно не сказано смотреть в другой репозиторий или общую продуктовую документацию.

## Правило навигации по коду

Для понимания устройства репозитория в первую очередь используй инструменты CodeGraph MCP.

CodeGraph предпочтительнее:
- поиска по файлам через grep
- последовательного чтения множества файлов
- разовых AST-скриптов
- широких проходов по файловой системе

Типовое сопоставление запросов и инструментов:
- «как устроен X?» → `codegraph_explore` или `codegraph_get_ai_context`
- «кто вызывает эту функцию/метод?» → `codegraph_get_callers`
- «что вызывает эта функция/метод?» → `codegraph_get_callees`
- «что сломается, если я изменю это?» → `codegraph_analyze_impact`
- «найди точки входа / хендлеры / команды» → `codegraph_find_entry_points`
- «найди связанные тесты» → `codegraph_find_related_tests`
- «суммаризируй модуль» → `codegraph_get_module_summary`

Переходи к grep/read только если:
- у CodeGraph ещё нет индекса для этого репозитория
- файл находится вне индексируемого workspace
- нужен именно исходный текст файла для редактирования или точной проверки.

## Workflow индексации

Перед глубоким анализом в новой сессии:
1. Проверь, активен ли CodeGraph для этого репозитория.
2. Если workspace не проиндексирован или индекс устарел, запусти `codegraph_reindex_workspace`.
3. После крупных рефакторингов, переноса файлов, изменения сигнатур, маршрутов или зависимостей — переиндексируй снова.

Не предполагай, что граф актуален после переключения веток, rebase или большого pull.

## Workflow редактирования

Перед изменениями:
1. Получи графовый контекст для затрагиваемого символа/файла.
2. Определи вызывающих и вызываемые сущности, импорты, точки входа и связанные тесты.
3. Оцени радиус поражения (blast radius) через CodeGraph перед изменением публичных интерфейсов.

После изменений:
1. Перезапусти релевантные тесты и линтеры.
2. Переиндексируй workspace, если изменилась структура (файлы, импорты, публичные API).
3. Повтори проверку вызывающих/вызываемых, если изменение затронуло интерфейсы или поток управления.

## Работа с документацией

Этот репозиторий — часть общей архитектурной документации продукта.

Если задача касается сравнения кода и документации:
- сначала используй инструменты CodeGraph для docs (`codegraph_index_markdown`, `codegraph_search_docs`, `codegraph_verify_design`, `codegraph_design_gaps`)
- не предполагай, что документация всегда актуальна
- явно фиксируй расхождения между реализацией и архитектурными документами.

## Работа с памятью (memory)

Если находишь что‑то полезное для будущих сессий, сохраняй это через инструменты памяти CodeGraph.

Сохраняй:
- результаты нетривиальных отладок
- архитектурные ограничения
- неочевидные инварианты
- особенности авторизации CLI, запуска команд в Docker, сохранения сессий и исполнения в контейнерах

Всегда ставь `agentSource` равным текущему агенту (например, `"claude"` или `"codex"`).

## Ожидания, специфичные для репозитория

Этот проект — сервис arch-docs. Обращай особое внимание на:
- поток запроса от API-слоя до выполнения CLI-команды
- авторизацию и жизненный цикл сессий для CLI агентов (Codex, Claude Code и др.)
- границы контейнеров (Docker) и изоляцию workspace
- поведение subprocess/PTY внутри контейнера
- наблюдаемость: логирование, метрики, обработку ошибок
- границы безопасности вокруг секретов, команд и прав записи в workspace.

## Безопасность и границы задач

По умолчанию не сканируй соседние репозитории.
Не опирайся на продуктовые предположения, если они не описаны явно.
Держи анализ локальным для этого репозитория, если явно не запросили cross-repo исследование.

## Предпочитаемый стиль работы

Работай точно и последовательно:
- сначала понимание структуры (через CodeGraph),
- потом планирование,
- затем изменения,
- затем проверка.

Избегай спекулятивных правок до того, как собран графовый контекст.
